# 系统性文献综述

## 输入

一个**研究问题**。越具体越好。用户给的是宽泛主题时，先把它收敛成可回答的问题，并在报告里写明收敛过程。

> 「大模型对编程效率的影响」→ 收敛为「在真实软件工程任务中，使用 LLM 编程助手对开发者完成时间与代码质量的影响，证据如何」

## 交付

一份可复现的综述。**检索策略必须记录到别人能重跑的程度**，这是系统性综述区别于随笔的核心。

## 执行步骤

1. **问题结构化**：拆成「研究对象 / 干预或变量 / 对照 / 结果指标」。不适用时说明为什么。
2. **制定检索策略**：检索词、同义词扩展、数据库、时间范围、语言范围。**先写策略再检索**，并原样记录到报告里。
3. **执行检索**：`search_scholar` 覆盖 OpenAlex 与 arXiv；重要论文用 `fetch_page` 读摘要原文或全文。记录每轮命中数。
4. **纳入 / 排除**：按预设标准筛。**记录排除数量与理由分布**，不只是留下的那几篇。
5. **方法学评估**：见 `rules/appraisal.md`。这是本技能的核心价值——一篇 RCT 和一篇问卷调查不能等量齐观。
6. **结论综合**：按结论归类，**特别标出互相矛盾的研究并分析分歧来源**（样本、方法、利益相关）。
7. **证据强度分级**：对每个主要结论给出强度判断与理由。
8. **缺口与建议**：哪些问题现有文献没回答。

## 不可破坏的约束

- **不能只看摘要下结论**。关键论文必须读到方法与结果部分；只读了摘要的要显式标注「仅摘要」。
- **样本量与研究设计必须记录**。n=12 的实验室研究与 n=4800 的现场研究，结论分量不同。
- **利益冲突要标注**。厂商资助的研究不是不能引用，但必须标明资助方。
- **引用数不等于质量**。高引可能是因为争议或综述属性。引用数只作参考指标，不作质量判据。
- **矛盾必须呈现**。如果文献结论分裂，报告必须如实反映分裂，不能挑一边写成共识。
- 每篇纳入文献给出可核验标识（DOI 或 arXiv ID）。

## 引用格式

正文只写 `[N]` 编号，完整网址集中到文末 `# 参考来源`。详见 [citation_format.md](rules/citation_format.md)。
