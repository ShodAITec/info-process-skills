# 竞品对标拆解

## 输入

用户给出**对标对象**，形式可以是：
- 明确的公司/产品清单（「对比 Notion、Coda、飞书文档」）
- 一个品类（「协同文档工具」）——此时你先检索确定 3–6 家主流玩家，并说明入选理由

如果用户提到了「我们」是谁，把我方也作为一列纳入对比，但严格区分「我方信息来自用户陈述」与「竞品信息来自公开检索」。

## 交付

一份 Markdown 对比报告。核心是**一张主对比表 + 逐项展开**，不是几段公司简介的堆砌。

## 执行步骤

1. **确定对比集**：锁定 3–6 家。太少没有参照系，太多表格失去可读性。说明为什么是这几家、排除了谁。
2. **确定对比维度**：先定维度再填内容，否则会变成各说各话。默认维度见 `rules/dimensions.md`，按品类增删并说明理由。
3. **逐家取证**：官网产品页、定价页、文档、客户案例页、第三方评测、用户社区吐槽。每家至少覆盖官方与非官方两类来源。
4. **填主对比表**：同一维度上各家必须可比。查不到就写「未公开」，不要用竞品的数据推测另一家。
5. **逐维度展开**：解释表里的差异意味着什么，而不是复述表格。
6. **形成结论**：谁在什么场景下赢、护城河在哪、可攻击的软肋在哪。

## 不可破坏的约束

- **定价必须标注口径与时间**。SaaS 定价经常分地区、分年付月付、有隐藏的席位下限。拿不到就写「未公开」，绝不按"同类产品大概多少"推算。
- **功能有无要有证据**。以官方文档或产品页为准；第三方评测与用户说法要标明出处和时间，因为功能会变。
- **客户案例要实名可查**。「某世界 500 强」这类无法核实的表述不计入证据，只能作为"厂商宣称"单独标注。
- **弱点部分要特别克制**。只写有公开证据支撑的（官方已知问题、用户社区高频抱怨、第三方评测结论），每条标注引用编号。不写推断性的负面评价。
- 区分四类信息并显式标注：**官方声明 / 第三方核实 / 用户反馈 / 本报告推断**。

## 引用格式

正文只写 `[N]` 编号，完整网址集中到文末 `# 参考来源`。详见 [citation_format.md](rules/citation_format.md)。
