# 他山见闻｜周刊功能说明书

## 1. 这份周刊解决什么问题

他山见闻面向希望持续阅读海外优质长文、但缺少时间逐个平台检索和完整阅读的中文专业读者。它从人文社科、商业管理、金融财务、经济和思想文化领域寻找值得阅读的文章，经过全文核验、编辑筛选和中文精读加工，形成一期可以直接阅读和分享的周刊。

它主要降低三类成本：发现成本——海外文章分散在出版物、作者网站和 Newsletter 中；判断成本——知名平台不等于每篇都值得读；理解成本——长文往往涉及背景、概念、证据与论证结构，直接阅读门槛较高。

最终产品不是新闻列表或全文翻译，而是一组经过编辑选择、能够共同解释本期重要问题的中文精读文章。

## 2. 适合谁使用

主要读者包括人文社科研究与从业者、商业管理与战略人员、金融财务和投资研究人员，以及关注思想、文化和公共议题的专业读者。

本周刊与 Insight Analysis、任何公司业务以及无人机、机器人等行业工作完全独立。即使某篇文章讨论 AI，系统关注的仍是文章本身的观点和论证，而不是为企业生成技术趋势判断或行动建议。

## 3. 文章从哪里来

系统通过三层来源建立候选池，但不会因为来源知名就自动入选：

示例网站不是固定名单。系统结合来源新稿、作者更新和主题检索寻找原始文章；开放渠道用于发现线索，不能代替原站全文。后台分别记录“哪些站点被定向搜索”“哪些页面实际打开”“看到了多少结果”“核实后有多少独立文章”，不同数字不能混用。

| 来源层 | 作用 | 典型渠道 | 使用原则 |
| --- | --- | --- | --- |
| 核心来源 | 稳定提供高质量候选 | Aeon、Noema、The New Yorker、Boston Review、HBR、MIT Sloan、FT、Reuters Breakingviews、NBER、IMF、BIS 等 | 直接进入候选池，仍需逐篇判断 |
| 作者追踪 | 长期跟踪稳定的优秀作者 | 学者、经济学家、投资人、管理学者、商业分析师、专业记者及独立作者 | 作者身份提高发现优先级，不替代文章质量 |
| 开放发现 | 发现新作者、新观点和新议题 | Substack、Medium、Hacker News、Reddit、Newsletter、搜索引擎和专业推荐 | 只作为线索，必须回到原始出处核验 |

用户提供的文章、链接或文件也会进入候选池，但不保证入选。如果全文不完整、原始出处无法核验、文章质量不足，或者与本期其他文章高度重复，系统会自动淘汰并在文末说明原因。

## 4. 文章怎样筛选

筛选不是把文章机械打分后取前五名，而是经过三层判断：

| 阶段 | 主要问题 | 处理方式 |
| --- | --- | --- |
| 硬性准入 | 是否能完整合法读取全文；作者、来源和日期是否明确；是否为广告、快讯或低质量转载；是否具有完整观点与基本论证 | 任一关键条件不满足即淘汰；无全文不精读 |
| 单篇质量 | 核心判断是否清楚；论证是否完整；证据是否可靠；观点是否有原创性、解释力或可迁移价值；是否足以支撑完整精读 | AI 根据文章类型综合判断，并保存自然语言去留原因，不用统一机械分数 |
| 整期编辑 | 主题和观点是否重复；来源是否过度集中；热门议题是否挤占整期；是否与历史刊期重复；文章之间能否形成共同问题与互补关系 | 选择一组能够构成一期周刊的文章，而不是五篇互不相关的“高分文章” |

不同领域的判断重点有所区别：人文思想更关注原创性、理论深度、历史背景和解释力；商业管理更关注因果逻辑、案例质量、可迁移性和决策价值；金融经济更关注数据来源、机制解释、假设条件和风险边界。

默认候选漏斗为：初始发现 50–150 篇 → 基础过滤 20–40 篇 → 完整阅读 10–15 篇 → 编辑短名单 6–8 篇 → 最终目标 5 篇。数量只是检索参考，质量不足时不会凑数。

每期文末运行附录列出逐站覆盖、各阶段进入／通过／淘汰数量，并按发布日期不符、全文不可读、来源不明、重复、单篇质量、整期主题重叠等**首要原因**拆分淘汰量。系统依据当次台账计算；历史某期未记录的访问量与初始结果数不会用上述目标数补齐。

## 5. 五篇文章怎样整合成一期周刊

系统先分别理解文章，再进行跨文章编辑。完整流程如下：

| 流程 | 形成的结果 |
| --- | --- |
| 候选发现与原始页面核验 | 确认标题、作者、日期、来源、直接链接和全文状态 |
| 同期与跨期去重 | 删除转载、重复文章和底层观点高度相同的内容 |
| 全文阅读与证据记录 | 提取核心判断、论证步骤、关键证据、假设和限制 |
| 单篇质量判断 | 判断是否值得为目标读者投入完整精读篇幅 |
| 整期组合 | 控制主题与来源集中度，寻找互补、对立或递进关系 |
| 本期核心观察 | 从多篇文章中提炼共同问题、分歧和趋势，而不是重复摘要 |
| 中文编辑加工 | 每篇形成推荐语、文章解读、解释性配图和“另一面” |
| 质量检查与打包 | 从 Markdown 生成同内容的离线 HTML，检查链接、图片、篇幅、术语、运行记录和 ZIP 完整性 |

因此，周刊的编辑对象不仅是单篇文章，也是文章之间的关系。栏目名称根据当期素材动态生成，不强制每期都平均覆盖所有领域。

## 6. 每篇文章最终包含什么

每篇默认采用稳定但不过度拆分的结构：中文编辑标题；一句话推荐；“文章解读”中的原文链接、作者背景、来源和发布日期；一张与文章直接相关、逐图说明来源的配图；2–4 个连续自然段，依次覆盖作者核心判断、论证如何成立、关键证据和对目标读者的理解价值；最后用“另一面”说明证据限制、反方观点或适用边界。

普通单篇正文控制在约 1,000–1,300 个中文字符，复杂文章可到 1,500。所有文章都采用完整精读，不使用“一篇精读＋四篇简读”的结构。

## 7. 配图和文件怎样交付

每篇文章配置一张专属配图。系统先查看原文页面，优先选择与文章内容相关、可以核实作者/摄影师/插画师署名并确认有权在可分享周刊中使用的原图。图片存在并不意味着可以直接复制；若原文没有合适的配图，或无法确认复制与离线分享所需的使用条件，就记录原因并用 AI 生成一张解释性图。图下分别有“配图说明”和“图片来源”：前者解释画面，后者标明原文页面链接与创作者、使用依据，或明确“AI 根据原文论证生成，非原文配图”。

周刊以“他山见闻”作为读者侧刊名。卷首固定阅读说明明确：本期文章内容（含配图）由 AI 辅助生成，并经过编辑加工和校验；周刊只提供中文导读与评论，不直接翻译原文，作者观点以原文为准。紧接着展示“内容周期”和“撰文时间”，后者是文章原稿写成的北京时间，精确到秒。检索截止留在文末后台运行记录，不单独占据读者首页。每张图片实际来自原文还是 AI，以图片下的来源说明为准。最终交付一个 ZIP，解压后包含同内容的 Markdown 和 HTML，以及一个 `images/` 文件夹。Markdown 图片使用相对路径，可在 Typora 中显示，分享 Markdown 时请连同 `images/` 一起分享。HTML 自带配图与排版样式，可单独复制或发送给他人，断网后直接双击在浏览器中阅读。HTML 不含可点击的超链接：原文标题下单列“原文网址”，其他引文名称下单列“引用网址”，保留完整地址以供选择和复制；Markdown 可继续保留原文链接。

两种格式均保留文末“Skill 系统运行记录”，供后台核查实际候选漏斗、淘汰原因、异常、链接与配图。HTML 中默认折叠该附录，读者可主动展开；该附录不属于读者正文。附录只写定稿时已经核验的事实；离线 HTML 与最终 ZIP 的生成后校验结果随交付说明反馈，避免预先把尚未执行的校验写成“通过”。若当期无法进行浏览器断网实测，会明确告知未验证，不会冒称已通过。

## 8. 如何提出需求

最简单的调用方式是：“使用他山见闻（ai-research-digest），筛选最近 7 天海外优质文章，生成一期中文精读周刊。”也可以补充统计周期、重点主题、目标读者、期望篇数、指定作者或候选文章。

系统默认全程自动完成，不要求用户中途选择文章。正式周刊无法完成时，会输出最终执行报告并说明无法完成的原因，而不会伪造筛选结果。
